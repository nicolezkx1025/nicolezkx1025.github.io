研究方向更多：展望细节 → 📫

一句话

让智能系统在真实世界里，可靠地长期运行。

我把注意力从“模型能做什么”移到“模型什么时候不可信”，是因为在工程里这两件事是同一个问题的两端：能力决定上限，可信度决定它能不能被交付。

我关注的四个问题

首页那张卡片里的四条，就是我现在把精力放在哪里。

1. 退化条件下的可信度

传感器退化、分布漂移、输入越界之后，状态估计与策略还值不值得信。切口有三个：不确定性量化（把“有多不确定”变成可用的信号）、失效识别（什么时候该说“我不知道”，而不是给一个看起来正常的输出）、降级与回滚（不可信时系统如何退到一个安全的档位）。

2. 从感知到决策的闭环

把状态估计、在线自适应与动作接成一条可信链路：世界模型负责预测，持续内部状态负责跨时间的一致性，在线自适应负责漂移，端到端集成负责让这些真的跑在同一个系统里。

3. 智能体的工程闭环

数据、训练、评测、部署——让能力按轮次累积，而不是靠一次性调参：Agent 的反思与纠错、多轮对齐、评测闭环与数据飞轮。这一条是我目前工程经验最厚的部分。

4. 训练与推理基础设施

训练／推理链路的工程实现与优化：分布式训练、推理加速、并发与延迟。很多“模型不行”的问题，实际上卡在这一层。

起点：一个四旋翼

这条线有一个很具体的起点。我的本科毕业设计是四旋翼飞行器的自动控制算法：STM32 主控 + MPU6050 惯性测量，用 Mahony 互补滤波做姿态解算，用双环 PID 做控制。

当时最直接的体会是：姿态估计一旦不可信，控制器再准也没有意义；敢不敢给控制量，取决于你对当前状态有多确定。这个“估计可信，控制才敢动”的直觉后来一直跟着我——从复杂表格结构化里的置信度判断，到大模型推理里“什么时候应该拒答”。

它也是我为什么把“退化条件下的可信度”放在第一条的原因。

这条兴趣线的形状

Hidden State 表示 → 不确定性量化（UQ）→ 世界模型 → 持续内部状态 → 自主导向智能体（Self-directed Agent）

从底层的隐状态表示出发，经过不确定性量化、构建世界模型、形成持久内部状态，最终演化出具备自主性的智能体。三个子方向：

可观测的智能表示

隐状态空间是否存在稳定、可解释、可迁移的结构；不同模态之间如何形成共享状态空间；能否借助数学方法提升内部状态的可观测性。

可信的世界模型

让智能体不仅能够预测未来，还能给出预测的可靠程度——不确定性传播、风险边界建模，以及在传感器退化条件下的失效识别。真正难的不是“预测得准”，而是“知道自己有多不确定”。

持续自主智能

长期记忆结构与周期性的离线隐状态重构机制，使系统在缺少外部任务时仍能保持状态连续，并逐步由内部状态形成下一阶段目标。

关于这两条线的完整推演（含"镜像自我认知测试"这个框架与可搬运的控制论工具箱），见：这次偏移是我还是世界:镜像自我认知测试下的 TTT 与 RSI。

方法取向

把机器人学中已相对成熟的状态估计与可观测性分析思路，引入以大模型为主体的智能系统：为“隐状态”建立可观测性，为“预测”配套不确定性，为“长期运行”设计状态重构机制。

我认为未来智能的进展，可能不只来自更大的模型规模，而取决于三个基础问题的答案：智能如何形成内部状态、内部状态如何被观测与量化、智能体如何基于长期状态产生自主目标。

我对两条技术线的理解：TTT 与 RSI

技术栈说明我会用哪些工具；下面两条是我对方向的判断。它们分别对应前面第 1 条与第 3 条问题，也共享同一个前提：系统必须知道自己什么时候不可信。

TTT：要分两层看，别混着用

架构层：把“在测试时做梯度下降”当作序列模型的隐藏状态更新机制，用一层可微的在线学习替代注意力／RNN 状态——这是结构选择，解决“表达力从哪来”。适配层：模型结构不动，推理时用无标注测试流在线更新，对付分布漂移（熵最小化、伪标签自训练、归一化统计量更新）——这是部署问题，解决“漂移了怎么办”。

我的判断：在低容错场景里，适配层的 TTT 是生存题而不是加分题。它有一个内生风险——在线自适应的目标函数（熵最小化、伪标签一致性）全部建立在“当前输入可信”这个前提上；前提一碎，模型会朝“更自信”而不是“更正确”的方向更新，收敛到一个自信的错误上。所以没有门控的在线自适应，在退化场景下成功率往往先升后降。工程上必须配套三件事：可信度信号（用估计器残差、预测与观测的动力学不一致性做判据）、更新预算（幅度与频次受限）、可回滚（每次自适应都能撤销）。

RSI：不是一个技术，而是一个性质

我把它拆成一条阶梯，用来区分“在自我改进”和“真的递归”：L0 人工设计的 Agent（脚手架写死）→ L1 Artifacts 自改进（Agent 迭代产出物，脚手架不变，绝大多数 coding agent 在这一层）→ L2 Harness 自改进（Agent 改自己的 prompt／skill／memory／路由）→ L3 双层循环（外层 Agent 优化内层 Agent 的代码，只有“比当前最优强”才采纳，这是真·递归的起点）→ L4 权重与 Harness 联合 → L5 完整 RSI。

我的判断：近期最现实的发力点在 L2，而不是 L5 ——改 harness 不动权重就能拿到收益，且不挑模型；真正够得上递归的案例极少。但无论在哪一层，自进化系统都得先回答三个门槛问题：验证信号（改进必须由可验证信号驱动，否则就是 reward hacking）、评测诚实性（预算对等、训练集与评测集分离、held-out 验证，否则“多花预算”会伪装成“学会了进化”）、算力回馈（改进的收益要能覆盖改进的成本，递归在经济上才成立）。

边界声明：以上是判断，不是实验结果。我没有在真机或大规模系统上验证过其中任何一条；写在这里，是为了被反驳。

我关心的很多问题，正是从这些真实系统里长出来的：在低容错、强约束的场景中，算法要可靠，而不只是“效果好”。
